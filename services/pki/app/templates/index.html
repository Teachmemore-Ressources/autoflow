Configuration LDAP / Active Directory

La configuration est sauvegardée dans /data/pki/ldap_config.json et prend effet immédiatement.

Active Directory utilise sAMAccountName et la recherche de groupe récursive.
ldaps:// (port 636) — chiffrement TLS, recommandé en production.
ldap:// (port 389) — non chiffré ou avec STARTTLS ci-dessous.
Non compatible avec ldaps://. À utiliser avec ldap:// port 389.
Compte de service (lecture annuaire)
Laissez vide pour conserver le mot de passe existant.
{username} est remplacé par le login saisi au moment du login.
Mapping groupes → rôles PKI
Renseignez le DN complet du groupe LDAP/AD pour chaque rôle PKI.
Un utilisateur membre de plusieurs groupes obtient le rôle le plus élevé (admin > operator > viewer).
Les champs laissés vides désactivent le rôle correspondant.
Certificat TLS (LDAPs)
Si le serveur LDAP utilise un certificat signé par votre PKI interne, indiquez le chemin du PEM de votre CA ici.
Laisser vide si le certificat est signé par une CA publique (Let's Encrypt, DigiCert…).
Décocher uniquement en environnement de test — ne jamais désactiver en production.
Si décoché, toute authentification est bloquée lorsque le serveur LDAP est inaccessible.

📋 Exemples de paramètres

Active Directory
URLldaps://dc01.corp.lan:636
Bind DNsvc-pki@corp.lan
Base DNCN=Users,DC=corp,DC=lan
Filtre(sAMAccountName={username})
Groupe AdminCN=PKI-Admins,OU=Groups,DC=corp,DC=lan
OpenLDAP
URLldaps://ldap.corp.lan:636
Bind DNcn=svc-pki,ou=services,dc=corp,dc=lan
Base DNou=users,dc=corp,dc=lan
Filtre(uid={username})
Groupe Admincn=pki-admins,ou=groups,dc=corp,dc=lan
